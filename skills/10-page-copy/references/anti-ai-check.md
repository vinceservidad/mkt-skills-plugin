# Anti-AI check (applies to everything written)

Run this as a second pass before saving or delivering copy. Skip code and data tables.

First, the reader. Name who reads this and what they need from it. Cut any sentence that doesn't serve that. Write each line the way a person would say it out loud to that reader.

Then the whole piece. These six matter more than the sentence fixes below. When two rules clash, pick the version that sounds natural read aloud.

1. Lists inside a sentence: 4 items at most. Keep the ones the reader needs. Move a longer list to bullets.
2. One point, one proof. Back a claim with its strongest fact or figure, then move on. Don't stack details to look specific.
3. Match terms to the reader. Use the exact technical or platform term when the reader works with it or will act on it. Use plain words when they don't.
4. Don't string labels and figures together like a table row. Put them in a sentence a person would say, or in a real table.
5. Shape: no two paragraphs in a row built the same way. Vary how many sentences each has. No more than two sentences in a row open the same way.
6. Say each thing once. Specific means one detail that belongs only to this subject. It doesn't mean a longer list.

Then the sentence fixes. Fix these where they show up:

1. "It's not X, it's Y" and "Not a X. Not a Y. A Z.": say Y. Keep a contrast only when the reader really believes X.
2. Question hooks and rhetorical setups ("What if I told you", "Plot twist:"): open with the answer, the result or the number.
3. Buzzwords (game-changer, unlock, leverage, elevate, delve, robust, streamline, supercharge, harness, transformative): use plain words. Keep a word when it's the exact platform term.
4. "What do you think?" endings, mic-drop lines, recaps ("Overall", "In conclusion"): end on the point.
5. Groups of three by habit (bullets, examples, sentences per paragraph): use the count the content has.
6. Vague claims: use a real figure from the user's notes, the data or a named source. If there is none, cut the claim or mark the gap.
7. Colon reveals ("The best part: it learns."): write a plain sentence. Use colons only for lists, labels and quotes.
8. Trailing "-ing" clauses that claim meaning (highlighting, showcasing, underscoring): cut them or state the fact.
9. Weasel attribution ("experts agree", "studies show"): name the source or cut the claim. Never invent a source.
10. Synonym cycling (agent, then assistant, then tool): pick one name per thing and keep it.
11. Dramatic fragments ("That's it. That's the whole thing."): join them into a full sentence. A short sentence that carries a fact is fine.
12. Em dashes: none.
13. No emoji in headers, no mid-sentence bold.

Last, reread the whole piece once as the reader. If it reads like a spec sheet or a checklist, rewrite the weakest paragraph from scratch. Don't patch it.

### When editing the user's own draft

Keep the user's voice (their hedges, bluntness, asides and long spoken sentences), make the smallest edit that fixes the problem, and show the draft, then a short "What changed" list.
